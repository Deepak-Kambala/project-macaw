## 1. Executive Summary

Milestone 5 reported a 31-byte test program synthesized by `aeon_r2_mini_assembler.py` and claimed 100% round-trip success against its own decoder (`verify_aeon_r2_isa.py`).

Because that verification was self-referential (both the encoder and decoder were written with the same initial assumptions), Milestone 6 constructed an **independent decoder** (`scripts/milestone6/validate_assembler.py`) built directly from the Ghidra SLEIGH architectural specification.

### Key Finding:
All 11 instructions (31 bytes) are **confirmed legal Aeon R2 machine code**. Furthermore, the independent validation resolved a subtle decoding discrepancy in Milestone 5:
- In Milestone 5, `bn.lwz r10, 8(r1)` was printed as `bn.lwz r10, 0xa(r1)` by the Milestone 5 decoder because it read the raw byte `0x0A` (`(simm2_6 << 2) | uimm0_2`).
- The independent SLEIGH decoder correctly extracts `i24_simm2_6 = (val >> 2) & 0x3F` and computes the effective memory offset as `i24_simm2_6 << 2 = 8`.
- The encoding `0x0A` generated by the assembler is verified to be the mathematically correct hardware representation of offset 8.

## 3. Deep-Dive on `bn.lwz` Offset Resolution

The SLEIGH definition for `bn.lwz` specifies:
```sleigh
i24_mB_16: i24_simm0_8_masked(i24_rA) is i24_simm0_8 & i24_rA & i24_simm2_6 [ i24_simm0_8_masked = i24_simm2_6 << 2; ] {
    local ea = i24_rA + i24_simm0_8_masked;
    export ea;
}
:bn.lwz i24_rD, i24_mB_16 is i24_uimm0_2 = 2 & i24_rD & i24_mB_16 { i24_rD = *:4 i24_mB_16; }
```
- In hardware, bits `[1:0]` of the instruction are `0b10` (`uimm0_2 = 2`), identifying the instruction as `bn.lwz` rather than `bn.sw` (`0b00`).
- Bits `[7:2]` are the signed immediate `simm2_6`.
- For `offset = 8`: `simm2_6 = 8 >> 2 = 2` (`0b000010`).
- The byte containing `simm2_6` and `uimm0_2` is `(2 << 2) | 2 = 0b00001010 = 0x0A`.
- The assembler produced `0x0A`.
- The independent decoder computes:
  $$\text{Effective Offset} = \left(\frac{\text{val} \gg 2}{1} \& 0x3F\right) \ll 2 = 2 \ll 2 = 8$$
- This confirms that both the assembler encoding and the hardware execution target match precisely.
