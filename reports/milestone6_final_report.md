## 3. Aeon R2 ISA Findings

The Aeon R2 core is an OpenRISC-derived architecture with proprietary variable-width extensions:
- **Endianness:** Strictly **Big Endian**.
- **Register File:** 32 32-bit registers (`r0`–`r31`). `r0` is hardwired to 0. Writes to `r0` are discarded.
- **Execution Units:** Supports 16-bit (`bt.*`), 24-bit (`bn.*`), and 32-bit (`bg.*`) instructions intermixed sequentially in memory.
- **Alignment:** Instructions are packed without mandatory 4-byte padding. Subroutines can contain 3-byte instructions, placing subsequent instructions on arbitrary byte offsets.

## 4. Instruction-Width Validation

Independent verification confirmed that the upper 3 bits (`Bits [7:5]`) of byte 0 unambiguously govern instruction length:

$$\text{Length} = \begin{cases} 
24\text{ bits (3 bytes)} & \text{if } (B_0 \gg 5) \in \{0, 1, 2, 3\} \iff B_0 \in [0x00, 0x7F] \quad [bn.*] \\
16\text{ bits (2 bytes)} & \text{if } (B_0 \gg 5) = 4 \iff B_0 \in [0x80, 0x9F] \quad [bt.*] \\
32\text{ bits (4 bytes)} & \text{if } (B_0 \gg 5) \in \{5, 6, 7\} \iff B_0 \in [0xA0, 0xFF] \quad [bg.*]
\end{cases}$$

This classification was independently confirmed via:
1. `shinyquagsire23/ghidra-aeon/data/languages/aeon_ORBIS32.sinc`:
   - Line 145: `with : i16_decoder = 4`
   - Line 192: `with : i24_decoder = 0 | i24_decoder = 1 | i24_decoder = 2 | i24_decoder = 3`
   - Line 420: `with : i32_decoder = 5 | i32_decoder = 6 | i32_decoder = 7`
2. MStar Chakra3 kernel header `r2_backtrace.c`:
   - `OP_R2_BT_ADDI_PFX 0x27` (top 3 bits = 4)
   - `OP_R2_BN_ADDI_PFX 0x07` (top 3 bits = 0)
   - `OP_R2_BG_ADDI_PFX 0x3F` (top 3 bits = 7)

## 10. Graphics API Investigation

Binary re-examination in `decompressed_main.bin` produced the following re-classifications:
1. `0x17bd3e` (`MDrv_GE_FillRect`), `0x17bd4f` (`MDrv_GE_DrawLine`), `0x17bd60` (`MDrv_GE_SetDstBuffer`), and `0x17bd9d` (`MDrv_GE_SetClipWindow`) reside in `.rodata` and are **string table identifiers**.
2. They are used as diagnostic format parameters in driver error handling:
   ```text
   0x17bcf0: %s: address fail\n\x00
   0x17bd02: %s: pitch fail\n\x00
   ```
3. The executable implementations of these functions reside in `.text` (`0x000000`–`0x150000`).
4. While the high-level semantic behavior of these functions is well understood from MStar Utopia documentation, their exact binary entry points and compiler calling conventions in this specific binary build remain to be isolated.

## 13. Remote-Control Input Investigation

Documented in `reports/milestone6_input_pipeline.md`:
1. Physical IR capture and translation to scan codes is handled by MStar RIU MMIO registers and `drvIR`.
2. Inter-thread message dispatch is handled by MStar Utopia Mailbox (`MDrv_MBX_SendMsg`).
3. ZUI window procedure routing uses format string `u8WinProcID= %d \n` and `_eActiveOSD=%d\n`.
4. While `MApp_ZUI_ACTagingmenu.c` is verified to exist in `.rodata`, attempting to patch or redirect window procedures without disassembled entry points and stack frame verification poses a high risk of immediate firmware crash.

## 14. Safety and Recovery Considerations

1. **Host-Side Only:** All work in Milestone 6 was conducted strictly on the host system. No communication was attempted with the television.
2. **Firmware Hash Preservation:**
   - `Samsung-TV-Homebrew/firmware/T-MXL0MASC.bin`: `f02cbf9ecf87087ea85826584cc9ad949b13d1ff404b1fe8888323b0f4ed52d5`

3. **Hardware Recovery Boundary:** In-circuit SOIC-8 SPI flashing remains hazardous without pulling the MStar SoC `RESET#` pin low due to 3.3V rail back-powering and SPI bus contention. MStar I2C ISP remains the preferred physical recovery path.

## 16. Milestone 7 Recommendations

1. **Symbolic Binary Lifting:** Use Ghidra headless scripts with `shinyquagsire23/ghidra-aeon` to cross-reference `.rodata` diagnostic strings (`%s: address fail`) back into `.text` to pinpoint the exact executable entry points of `MDrv_GE_FillRect` and `MDrv_GE_DrawLine`.
2. **ZUI Window Procedure Table Reconstruction:** Trace references to `u8WinProcID` format string (`0x16ca03`) in `.text` to recover the array of function pointers corresponding to `ACTagingmenu` and `ACTshopmode`.
3. **Extended Instruction Set in Emulator:** Add conditional branch variants (`bg.bles`, `bg.bgt`, `bn.blesi`), load/store byte/halfword (`bn.lbz`, `bn.lh`), and logical shifts (`bn.slli`, `bn.srli`) to the emulator to support larger C-compiled blocks.
4. **Standalone Binary Payloads:** Build a host-side toolchain flow that compiles a complete C-based Snake game to an Aeon R2 binary blob and verifies its execution inside the emulator.
